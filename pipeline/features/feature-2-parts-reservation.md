# Feature 2 — Parts Reservation

| Field | Value |
|---|---|
| **Status** | Draft requirements — awaiting human review |
| **One-line intent** | Let a dispatcher check parts stock and reserve the required parts for an already-scheduled job. |
| **Depends on** | Feature 1 decision, **standard travel buffer per job is 45 minutes**, and Feature 1's scheduled job record. Each reservation must reference an existing scheduled job. The buffer remains unchanged; this feature does not calculate calendar capacity or use travel time to determine stock. |
| **In scope** | **User story:** As a dispatcher, I can see the available quantity for a part and reserve the needed quantity for an already-scheduled job. **Draft assumptions to confirm:** the dispatcher supplies a part ID and a positive requested quantity; no inventory quantities or default quantities are prescribed. When available stock is at least the requested quantity, reserve exactly that quantity and report success. When stock is greater than zero but below the request, report available and short quantities and make no reservation automatically. When stock is zero, report out of stock and make no reservation. Only existing, already-scheduled jobs are eligible. An identical repeat request for the same job, part, and quantity must not decrement stock or create a second reservation; changing or extending a reservation is not supported in this feature. |
| **Out of scope** | Automatic or manual backorder creation, backorder fulfillment, procurement/replenishment, low-stock alerts, deriving required quantities from a bill of materials, reservation editing/cancellation/release, and changing a job's schedule or its 45-minute travel buffer. No stock levels, fixture quantities, or other business thresholds are prescribed. **Draft questions for human review:** Should a partial quantity be reservable in the same operation, or should the dispatcher submit a reduced quantity separately? Should zero-stock requests create a backorder record? Should dispatchers be able to change or release existing reservations? |
| **Definition of Done** | - A dispatcher can check a part's available quantity in the context of an existing scheduled job and request a positive quantity. <br>- A request with sufficient stock, including an exact-stock match, reserves exactly the requested quantity, returns a clear success result, and updates available/reserved quantities consistently. <br>- A partial-stock request reports available and short quantities and leaves stock and reservations unchanged. <br>- A zero-stock request reports out-of-stock, creates no reservation or backorder, and leaves stock unchanged. <br>- An invalid/malformed job or part ID is rejected as a validation error; a well-formed unknown job or part ID is reported as not found. A job that exists but is not scheduled is rejected clearly and creates no reservation. <br>- Repeating an identical job/part/quantity request does not reserve or decrement stock twice. <br>- Requests that would exceed available stock, including competing requests, cannot leave available stock below zero or create an over-reservation. <br>- **Success metrics (fixture-based acceptance):** all full-stock scenarios reserve the exact requested amount; all partial/out-of-stock and invalid/ineligible scenarios create zero reservations; duplicate submissions cause zero additional stock decrement; no scenario produces negative available stock. Test fixtures use relative quantities and do not establish production stock levels. |
